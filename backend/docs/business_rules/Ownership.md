# Ownership Rules

**Version:** v2.0  
**Purpose:** Defines the authoritative owner of every derived field, balance, stock quantity, and projection in the Dairy ERP system. This document prevents conflicting writes, duplicated business logic, and data corruption.

---

## Core Principle

Every field must have exactly one authoritative owner.

A field may be:

- **Source Data** (entered by users or generated by business events)
- **Derived Data** (calculated from source data)
- **Cached Projection** (stored for performance)

Only the designated owner may modify a field.

## Product Stock Ownership

### products.current_stock

**Type:** Cached Projection  
**Owner:** `StockService`  
**Updated By:**

- `StockService.applyMovement()` (called by Domain Hooks)

- `purchase_hooks` (orchestrator only)

## Attendance Ownership

### attendance.status

**Owner:** `payroll_hooks`  
**Allowed Values:** `draft`, `locked`  
**Rule:**
Payroll approval locks attendance records only for the same payroll period.

**Example:**
Approving May payroll locks May attendance.  
June attendance remains editable.

## Ledger Event Keys

Ledger records generated by `LedgerService` must inherit the originating transaction event.

**Example:**

Transaction:
event_key = sales_order:123:delivered
Generated Ledger:
event_key = sales_order:123:delivered

This guarantees end-to-end idempotency.

## Hook Responsibilities Summary

### Domain Hooks (Orchestrators)

**Examples:** `sales_hooks`, `purchase_hooks`, `production_hooks`, `payroll_hooks`, `expense_hooks`

**Responsibilities:**

- Open transaction boundaries (`runInTransaction`)
- Create source-of-truth records (movements, transactions)
- Call Services to update projections
- Coordinate multi-step workflows

**Must NOT:**

- Calculate projections directly
- Modify stock fields directly
- Create ledger records directly

---

### Integrity Hooks (Guards)

**Examples:** `finance_hooks`, `inventory_hooks`

**Responsibilities:**

- Validate data integrity
- Enforce immutability rules
- Enforce append-only rules
- Generate reference numbers
- Log audit events

**Must NOT:**

- Execute business logic
- Update projections
- Create ledgers or movements

---

## Golden Rules

| Rule                                       | Status    |
| ------------------------------------------ | --------- |
| One field = One owner                      | Mandatory |
| Flutter never updates projections directly | Mandatory |
| Domain hooks orchestrate, services execute | Mandatory |
| Services own all projections               | Mandatory |
| Integrity hooks validate, not execute      | Mandatory |
| Services never open transactions           | Mandatory |
| Domain hooks own transaction boundaries    | Mandatory |
| Reversals create new records               | Mandatory |
| Posted records are immutable               | Mandatory |
| Every generated record must be idempotent  | Mandatory |
